# 本地 Web 客户端

svntui v0.3.0 增加浏览器界面，操作当前电脑上的 SVN 工作副本。程序包含全部网页资源，运行时不需要 Node.js 或 CDN；系统 `svn` 仍需单独安装并加入 PATH。

## 启动与停止

```bash
svntui web
svntui web "/path/to/working-copy"
svntui web --no-open --port 17890 "/path/to/working-copy"
```

Windows PowerShell 示例：

```powershell
svntui web "C:\work\project"
```

默认仅绑定 `127.0.0.1`，系统自动分配端口并打开默认浏览器。`--port` 可指定 1–65535 的端口，0 表示自动分配；端口被占用时会明确报错。`--no-open` 适合手动复制终端中的首次访问链接。

没有指定目录时，在工作副本中启动会将其加入最近项目；在普通目录启动会显示已有项目和添加入口。显式指定无效的工作副本路径会报错。项目添加框接受本机目录路径，后端会验证 SVN 工作副本根目录；浏览器无需上传项目文件。

按 Ctrl-C 停止。服务会停止接收新操作，等待正在执行的写操作完成后退出。关闭标签页不会停止服务，也不会取消已确认的写操作。发生强制退出时，下次启动会读取真实工作副本状态，不自动重放提交或其他写操作。

## 本机会话与 SVN 认证

首次访问链接通过 URL 的 `#token=…` 片段携带一次性凭证。页面建立本机会话后立即移除片段；普通日志重定向只输出服务地址，不输出首次访问凭证。请在交互终端启动并使用自动打开的浏览器，或手动复制首次访问链接。

该入口用于本机个人使用，不提供局域网监听、远程账号或多人权限管理。不要分享首次访问链接。API 会校验浏览器来源和写请求凭证。

SVN 继续使用当前系统用户的认证与证书配置，Web 不保存密码。认证失败时，先在同一用户终端对该工作副本运行原生 `svn info` 或所需的 SVN 命令，完成认证或证书确认，再回到页面刷新。

## 日常流程

- **项目：** 命名项目与最近工作副本沿用 CLI/TUI 配置，移除记录不会删除项目目录。
- **工作区：** 按路径、状态、changelist 筛选，选择文件后查看统一或左右对照差异。隐藏的已选项仍须在最终确认中显示。
- **提交：** 同时核对文件、差异与多行说明，再进入实际目标确认。选择目录不会递归提交未选子文件；新增父目录需要一并明确选择。
- **更新：** 先检查远端变化，再确认执行，可指定目标文件或目录和修订。冲突留待复查，不自动解决。
- **还原与删除：** 高风险确认需要输入大写 `YES`；还原沿用 SafePoint 自动保护，无法完整保护时中止。
- **历史：** 可按文件、作者、日期、提交说明筛选并分页，查看变化路径和修订 diff。
- **冲突：** 对照 BASE、本地与远端，选择 SVN 支持的整版内容；也可在 IDE 处理后刷新并标记解决。属性与树冲突独立显示。仍有文本冲突标记时会阻止误标记。

提交草稿按项目保存在当前用户状态目录的 `web/` 下，刷新或重启服务后仍可恢复；提交成功后清空。页面会提示保存状态和保存失败，实际提交目标以最终确认页为准。

草稿并发校验作用于同一个 Web 服务进程；多个标签页请复用同一个服务地址。独立服务进程之间的草稿编辑不提供协作合并。

## 任务与恢复

确认写操作后，任务由 Go 服务继续执行；活动列表展示阶段、结果和错误，重新打开页面后可查询当前进程中的任务。服务重启后不会保留内存任务，但可查看已有的脱敏操作记录。

同一工作副本同时只允许一个 Web 写任务，并与 CLI、TUI 和已有自动任务共用跨进程写锁。工作副本被占用时会显示提示。确认前目标发生变化时，需要重新预览；不会自动重试提交。

写操作成功或失败后，页面都会刷新 SVN 状态。关联 SafePoint 可在活动面板中查看和恢复；快照恢复同样需要预览及风险确认。SafePoint 的版本和内容限制仍以 [工作流指南](workflows.md#safepoint-与性能边界) 为准。

二进制内容不展开为文本。大差异每页最多显示 1000 行，页码和范围会明确标示；搜索覆盖已读取的全文，匹配结果会跳转到对应页，统一与并排视图都支持。分页不会丢弃其他页的内容。

diff 或输出超过读取限制时会明确说明，不能将截断内容视作完整数据；完整补丁仍可通过 CLI 的 `patch export --output` 导出。

## 开发与构建

需要 Go 1.24+，重建网页使用 Node.js 24 和 npm。仓库提交已构建网页资源，因此仅构建 Go 程序可直接运行 Web：

```bash
go build -o svntui ./cmd/svntui
./svntui web
```

修改前端后先安装锁定依赖、检查并构建，再编译 Go：

```bash
cd web
npm ci --registry=https://registry.npmjs.org
npm run build
cd ..
go build -o svntui ./cmd/svntui
```

前端构建结果位于 `internal/webui/dist` 并嵌入 Go 程序。前端源代码、锁文件与构建资源必须同步提交，三平台发行包使用同一份网页资源。
